# `critique`

**When:** The user wants an honest review of a design (screenshot, page, app).

## Steps
1. State what the surface is for and whether it achieves that in 5 seconds.
2. Assess in this order: hierarchy & focal point, layout & spacing, typography, color & contrast, copy, interaction states, consistency with DESIGN.md, accessibility.
3. Run `design-sense check` on the source if available and include its P0–P2 findings.
4. Give a prioritised list: top 3 changes with the biggest impact, each with a concrete fix.
5. Note what works and should be kept.

## Checks before you finish
- [ ] Every point is specific (element + problem + fix)
- [ ] Priorities are ranked
- [ ] Separate taste from defects
- [ ] `design-sense check` run on changed files; P0–P2 fixed or explained

## Do
- Point at exact elements
- Offer a before/after description

## Don't
- Pad with generic praise
- List 20 equal-weight nitpicks
