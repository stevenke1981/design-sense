# `onboard`

**When:** First-run experience, empty states, or teaching the interface.

## Steps
1. Show value before asking for setup; defer sign-up/permissions until needed.
2. Empty states: say what goes here, why it is useful, and one action to fill it.
3. Teach in context (inline hints, tooltips) rather than multi-step tours.
4. Remember dismissals; never show the same tip twice.
5. Provide sample data or a demo file where possible.

## Checks before you finish
- [ ] User reaches first success in under a minute
- [ ] Every empty state has an action
- [ ] `design-sense check` run on changed files; P0–P2 fixed or explained

## Do
- Use real, short examples

## Don't
- Block the app behind a carousel of slides
